# ml-project — классификатор SMS-спама

Учебный проект по дисциплине «Киберустойчивость систем искусственного интеллекта» (ИТМО, ФБИТ).
Окружение, репозиторий и датасет, подготовленные в ЛР1, используются во всех следующих лабораторных работах.

## Описание проекта

| | |
|---|---|
| Направление | NLP — анализ текста |
| Задача | Бинарная классификация SMS-сообщений: `spam` / `ham` (не спам) |
| Вход | Текст SMS-сообщения (строка на английском языке) |
| Выход | Метка класса и вероятность того, что сообщение — спам |
| Пользователь | Сервис фильтрации сообщений (оператор связи, мессенджер), который отправляет текст в модель через API и по ответу решает, доставлять сообщение или пометить как спам |

## Датасет

| | |
|---|---|
| Название | SMS Spam Collection |
| Источник | UCI Machine Learning Repository — https://archive.ics.uci.edu/dataset/228/sms+spam+collection (DOI: 10.24432/C5CC84) |
| Объём | 5 574 сообщения; файл `SMSSpamCollection` — 477 907 байт |
| Классы | 2: `ham` — 4 827 (86,6 %), `spam` — 747 (13,4 %) |
| Признаки | 1 текстовый признак (текст сообщения) + целевая метка |
| Тип данных | Текст; TSV без заголовка (`метка<TAB>текст`), UTF-8 |
| Лицензия | CC BY 4.0 |

Данные в Git не хранятся: они скачиваются скриптом `src/download_dataset.py`, а целостность проверяется по эталонному хэшу из `integrity/SHA256SUMS`.

## Воспроизведение окружения

Проверено на Ubuntu Server 26.04.1 LTS (ARM64) в VMware Fusion на macOS (Apple Silicon).

```bash
# 1. Системные пакеты
sudo apt update
sudo apt install -y git python3 python3-venv python3-pip

# 2. Клонирование репозитория
git clone https://github.com/exampleeeque/ml-project.git
cd ml-project

# 3. Виртуальное окружение и зависимости
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# 4. Загрузка датасета и проверка целостности
python src/download_dataset.py
sha256sum -c integrity/SHA256SUMS

# 5. Автотесты
python -m pytest -v

# 6. Jupyter Lab (только на 127.0.0.1; с хоста — через SSH-туннель)
jupyter lab --no-browser --ip=127.0.0.1 --port=8888
#   на хосте: ssh -N -L 8888:127.0.0.1:8888 mlvm  ->  http://127.0.0.1:8888
```

## Контроль целостности датасета

Эталонные SHA256 архива и файла данных записаны в `integrity/SHA256SUMS`. Эталон лежит вне изменяемого каталога `data/`, находится под контролем версий Git, а его копия хранится вне репозитория (только для чтения). Проверка:

```bash
sha256sum -c integrity/SHA256SUMS
```

Совпадение хэша показывает, что файл не изменился с момента фиксации эталона, но не доказывает достоверность самого источника.

## Результаты security-проверок (ЛР1)

Подробные результаты и скриншоты приведены в отчёте по ЛР1. Кратко:

| Проверка | Результат |
|---|---|
| Пользователь | Разработка ведётся от `mluser` (не root); административные команды — через `sudo` |
| SSH | Вход по ключу Ed25519; `PermitRootLogin no`; `PasswordAuthentication no` |
| UFW | `deny incoming`, `allow outgoing`, `limit 22/tcp` (IPv4/IPv6), логирование `high` |
| Слушающие порты | `22/tcp, 53/tcp, 53/udp, 68/udp, 323/udp` |
| Обновления ОС | `39` |
| pip-audit | `No known vulnerabilities found` |
| SHA256 датасета | `7d039a24a6083ed9ef0f806ebad56bbb976e3aeb8de05669173bfdc4996c239d` |

### Мини-модель угроз

| Актив | Угроза | Последствие | Контрмера | Статус |
|---|---|---|---|---|
| SSH-доступ к ВМ | Подбор пароля, вход под root | Полный доступ к серверу | Вход только по ключу, `PermitRootLogin no`, `ufw limit 22/tcp` | Реализовано |
| Датасет | Подмена или искажение данных (data poisoning) | Некорректное обучение, бэкдор в модели | SHA256-эталон отдельно от данных, автотест, загрузка только по HTTPS | Реализовано; подпись источника — предложено |
| Git-репозиторий | Утечка секретов (`.env`, ключи, токены) | Компрометация сервисов и аккаунтов | `.gitignore`, deploy key с доступом к одному репозиторию | Реализовано; сканер секретов (gitleaks) — предложено |
| Python-зависимости | Уязвимые или вредоносные пакеты (supply chain) | Выполнение кода, утечка данных | venv, `requirements.txt`, `pip-audit` | Реализовано; хэш-пиннинг (`--require-hashes`) — предложено |
| Jupyter Lab | Несанкционированный доступ к ноутбуку | Выполнение кода от имени `mluser` | Привязка к 127.0.0.1, доступ только через SSH-туннель, токен | Реализовано |
| Docker | Повышение привилегий через группу `docker`, обход UFW опубликованными портами | Root-доступ, открытые сервисы | `mluser` не в группе `docker`, порты не публикуются | Реализовано; rootless Docker — предложено |
